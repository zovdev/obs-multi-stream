# OBS Multi-Stream

Одновременный стрим на **Twitch** и **YouTube** из одного OBS — одной кнопкой,
с единой панелью управления: авторизация → настройка → эфир.

Никаких ручных трансляций в YouTube Studio, копирования ключей и дублирования
настроек: плагин сам создаёт трансляцию, применяет название/игру/теги/превью,
поднимает оба RTMP-потока и ведёт объединённый чат.

## Возможности

- **Единая док-панель** (Custom Browser Dock): пошаговый визард — авторизация,
  настройки, эфирный экран со статусами, зрителями и чатом обеих платформ.
- **Вход без бумажной волокиты**: Twitch — код активации в панели (ссылка
  открывается в системном браузере), YouTube — вход прямо в панели OBS с
  авто-возвратом (клиент OBS встроен, свой Google-клиент не нужен).
- **Настройки трансляции**: название, описание, теги-чипы (как в YouTube:
  запятая/Enter — тег становится блоком с ✕, пробелы → подчёркивания),
  игра/категория с живым поиском, превью-микрокарточка (клик = замена).
- **Пресеты** с автосохранением: изменения выбранного пресета пишутся в него
  автоматически; последний активный пресет открывается сам.
- **Битрейт и дорожка звука отдельно для каждой платформы** (Twitch | YouTube),
  с предупреждением при превышении лимита Twitch (6000 Kbps по официальным
  рекомендациям).
- **Восстановление после сбоя**: если OBS/ПК упали во время эфира, следующий
  запуск **продолжает ту же трансляцию YouTube** (та же ссылка, чат и зрители),
  а не создаёт новую.
- **Чат YouTube без квоты API**: по умолчанию плагин читает чат как браузер
  без логина (внутренний анонимный канал YouTube) — мгновенно и не тратя
  дневную квоту Data API; при поломке канала автоматически переключается
  на официальный API (см. «Чат YouTube и квота API»).
- **Настройки расширения (⚙ в панели)**: источник чата YouTube, интервалы
  обновления зрителей обеих платформ, проверка/обновление токенов
  кнопкой — всё применяется на лету, без перезапуска OBS.
- **Кастомный формат чата**: сообщения собираются из тегов
  `<time> <source> <avatar> <username> <message>` в любом порядке
  (например `<time><avatar>[<username>] - <message>`) — с живым превью
  и подсказкой по всем тегам прямо в настройках.
- **Чат для показа на сцене**: отдельная локальная ссылка
  (`http://127.0.0.1:7664/overlay`) — прозрачная страница с копией чата
  для Browser Source OBS: сообщения исчезают через заданное время,
  старые вытесняются при превышении лимита — поверх стрима ничего
  не зависает.
- **Безопасное хранение**: токены — в одном зашифрованном файле
  (`secrets.dat`; Windows — DPAPI, другие ОС — потоковый шифр с отпечатком
  машины). Всё локально, телеметрии нет.

## Как это работает

Плагин — это Python-скрипт OBS + встроенный HTTP/WebSocket-сервер
(`127.0.0.1:7664` / `7665`), который отдаёт страницу док-панели и обменивается
с ней командами. Кодирование выполняют **настроенные в OBS кодеры стрима**:
основной выход OBS идёт напрямую в Twitch, а цель YouTube в плагине
[obs-multi-rtmp](https://github.com/sorayuki/obs-multi-rtmp) создаётся
со **всеми параметрами этого же кодера** (перезаписываются только битрейт
и дорожка звука). «Холостого» кодирования больше нет: было три
одновременных кодирования (Twitch + YouTube + выбрасываемый поток
в локальный RTMP sink), стало два.

```
OBS (основной выход, кодер из настроек вывода) ──► Twitch (RTMP)
     └─► obs-multi-rtmp: цель YouTube (тот же кодер + свой битрейт)
               ──► YouTube (RTMP)
       Python-скрипт ──► YouTube Data API (broadcast/превью/категория)
                      ──► Twitch Helix (ключ, title/игра/теги)
       Док-панель (CEF) ⇄ HTTP+WS ⇄ скрипт
```

Раздельные битрейты (например, Twitch 6000 / YouTube 9000 Kbps) требуют
двух кодирований — это архитектурный минимум. Понизить битрейт уже
закодированного потока без полного перекодирования нельзя: у H.264 битрейт
запечён в решениях кодера покадрово, а перекодирование (декод + повторный
энкод) стоит дороже кодирования с нуля. Дешевле всего два аппаратных
кодирования: если кодер в настройках OBS — NVENC/QSV/AMF, оба потока
кодируются GPU и почти не грузят CPU. Если одинаковый битрейт устраивает на
обеих платформах, obs-multi-rtmp умеет делить кодер основного выхода без
перекодирования — тогда кодирование будет одно (установите у цели YouTube
`video-config` в `<OBS_STREAMING_ENCODER>`).

## Требования

- **ОС: Windows** — плагин разрабатывался и проверялся только на Windows.
  На Linux/macOS не тестировался (пути к OBS и извлечение YouTube-клиента
  из бинарника — виндовые; теоретически Linux-пути в `config.py` есть,
  но работа не проверялась).
- **OBS Studio 30.2+** (работает и на 32.x — управление профилями идёт через
  obs-frontend-api напрямую).
- **obs-multi-rtmp 0.6+** (sorayuki).
- **Python**, который использует OBS, + два пакета:

  ```
  pip install -r requirements.txt
  ```

  (`websockets` — док-панель, `websocket-client` — чат Twitch,
  `Pillow` — необязательно, для автосжатия превью больше 2 МБ).
  obs-websocket Server не нужен.

  Пакеты ставятся в тот Python, который видит OBS (Windows: обычный `pip`
  при одном системном Python; иначе `"C:\\Путь\\К\\python.exe" -m pip
  install ...`).

## Установка

1. Установите **obs-multi-rtmp 0.6+**:
   https://github.com/sorayuki/obs-multi-rtmp — и перезапустите OBS
   (плагин должен появиться в меню Docks: «Multiple RTMP outputs»).
2. Папку `obs_multi_stream` добавьте в скрипты OBS:
   `Tools → Scripts → Script Files → +`.
3. Установите Python-пакеты (см. «Требования», `requirements.txt`).
4. Добавьте док-панель: `View → Docks → Custom Browser Docks`,
   URL: **`http://127.0.0.1:7664/`**

## Быстрый старт

### Шаг 1 — Авторизация

- **Twitch**: «Подключить Twitch» → в карточке появится код (клик —
  копирует; кнопка открывает `twitch.tv/activate` в системном браузере,
  код уже в ссылке) → подтвердить. Панель продолжится сама.
- **YouTube**: «Подключить YouTube» → **«Войти здесь — в панели OBS»**
  (панель уходит на страницу Google и возвращается автоматически) или
  «Во внешнем браузере» — системный браузер. Клиент OBS встроен в плагин,
  свой Google-клиент создавать не нужно (опция есть в «Расширенных»).

### Шаг 2 — Настройки

Все поля автосохраняются (~0.8 с после правки, индикатор «✓ сохранено»):

- **Название / Описание** — как обычно.
- **Игра** — начните вводить название: появятся подсказки (Twitch-игры +
  категории YouTube); Enter выбирает первую. После выбора — компактный чип
  с бейджем категории YouTube (клик по бейджу — уточнение, клик по чипу —
  редактирование).
- **Теги** — чипы как в YouTube Studio: запятая или Enter превращают текст
  в блок с ✕; пробелы внутри тега автоматически заменяются на `_`
  (транскоды/хэштеги не любят пробелы). Backspace на пустом поле удаляет
  последний тег.
- **Превью YouTube** — микрокарточка: клик по картинке заменяет файл,
  ✕ в углу убирает; поддерживается drag&drop (JPG/PNG до 2 МБ).
- **Битрейт и дорожка звука** — колонки Twitch | YouTube: степперы ±500
  и сегменты 1–6. Если битрейт Twitch выше 6000 Kbps — появится
  предупреждение (официальный рекомендуемый максимум; выше — возможны
  отключение транскодов и нестабильность).
- **Пресеты** — «＋» создаёт новый (поповер с именем); выбранный пресет
  обновляется автоматически при каждой правке настроек, отдельная кнопка
  перезаписи не нужна; ✎ — переименовать, ✕ — удалить. Последний выбранный
  пресет открывается сам при следующем запуске OBS.

Дорожка звука — какой «Трек 1–6» микшера OBS идёт в эфир платформы. По
умолчанию Трек 1 (на него звук источников OBS идёт изначально). Настраивать
стоит, только если вы развели звук по трекам: правый клик по источнику →
«Расширенные свойства звука» → галочки «Трек 1…6».

### Шаг 3 — Запуск

Кнопка **«▶ Запустить стрим (Twitch + YouTube)»**:

- Twitch: stream key через API, обновление названия/игры/тегов канала.
- YouTube: создание broadcast + переиспользуемый stream + привязка,
  категория, превью, автопереход в `live` (с ретраями).
- основной выход OBS (Twitch) и цель YouTube стартуют одной кнопкой:
  кодеры — из настроек вывода OBS; в панели — статусы, зрители и
  объединённый чат.

Остановка — «■ Остановить стрим»: трансляция YouTube завершается (`complete`),
профили OBS восстанавливаются из бэкапа. Если эфир был начат/остановлен
кнопкой OBS — плагин отслеживает это тоже.

### Если OBS или ПК упали во время эфира

Плагин сохраняет активную трансляцию YouTube в `live_session.json`. После
перезапуска OBS панель предупредит: «найдена незавершённая трансляция» — и
следующий запуск **продолжит её**: та же ссылка, тот же чат и счётчик
зрителей, без новой записи на канале. Twitch в восстановлении не нуждается —
название/игра просто применяются заново. Явная остановка («■») завершает
сессию; следующее нажатие «▶» создаёт новую трансляцию.

## Где хранятся данные

Всё — в одной папке (одна папка = полное удаление плагина):

| Путь | Что лежит |
|---|---|
| `<obs-config>/plugin_config/multistream/secrets.dat` | токены/клиенты (зашифровано) |
| `…/multistream/settings.json` | настройки стрима + последний пресет |
| `…/multistream/presets.json` | пресеты |
| `…/multistream/previews/` | файлы превью |
| `…/multistream/live_session.json` | активная трансляция (для восстановления) |
| `…/multistream/backup/` | бэкапы профилей на время эфира |
| `…/multistream/multistream.log` | лог плагина |

`<obs-config>`: Windows — `%APPDATA%\obs-studio`, macOS —
`~/Library/Application Support/obs-studio`, Linux — `~/.config/obs-studio`.
Диагностика сервера панели: `http://127.0.0.1:7664/debug`

Токены не покидают машину: шифрование секретов — DPAPI (Windows) или
потоковый шифр с отпечатком машины (другие ОС), запись атомарная.

### Про OAuth-клиенты и «секреты» в коде

Секретов в коде нет. `TWITCH_CLIENT_ID` в `config.py` — это публичный
client_id самого OBS (виден в любом его билде), пароль от него не нужен:
refresh идёт через официальный прокси `auth.obsproject.com`. Google-клиент
плагин **не хранит** — он извлекается из бинарника OBS на вашей машине
(тем же клиентом пользуется встроенная интеграция YouTube в OBS). Своё
приложение Google создавать не нужно, но можно («Расширенные» в панели) —
тогда квота YouTube API будет считаться на вашем проекте, а не на общем
клиенте OBS.

### Чат YouTube и квота API

Чат YouTube читается **двумя путями**, и по умолчанию (`YOUTUBE_CHAT_SOURCE =
"auto"` в `config.py`) плагин использует их каскадом:

1. **Анонимный путь (основной)** — так же, как страница чата
   (`youtube.com/live_chat?v=…`) работает в браузере без логина: скрипт
   берёт со страницы публичный ключ и continuation-токен и ходит тем же
   внутренним запросом `get_live_chat`, что и браузер. **Квота Data API
   не тратится вообще**, интервал опроса называет сам сервер (обычно 1–10 с,
   для активных чатов меньше, чем официальный минимум 5 с).
2. **Официальный Data API (фолбэк)** — если внутренний формат изменился или
   анонимные запросы блокируются (403/429), ридер переключается на
   `liveChatMessages.list` (5 единиц квоты за опрос) и раз в 10 минут
   пробует вернуться на анонимный путь. В логе панели видно, какой источник
   активен («анонимный источник» / «официальный API — квота тратится»).

Режимы `YOUTUBE_CHAT_SOURCE`: `"auto"` (по умолчанию) — каскад с фолбэком;
`"innertube"` — только анонимный путь (квота не тратится никогда, но при
поломке чат замолчит до восстановления); `"official"` — только Data API,
как в версиях до 3.23.

**Важно**: анонимно можно только читать. Отправка сообщений и модерация
через OAuth не затрагиваются — они и так идут официальным путём.

**Зрители**: счётчик зрителей YouTube опрашивается раз в 15 с
(`YOUTUBE_VIEWERS_INTERVAL_SEC`, официальный `videos.list`, 1 единица квоты;
Twitch — раз в 30 с). Квота отслеживается общим трекером с сбросом в
полночь по тихоокеанскому времени (как у Google); при расходе >70%/90%
от дневного лимита интервал опроса зрителей автоматически растягивается
(30/60 с), а при исчерпании квоты (403) чтение чата встаёт на паузу до
сброса — зрители и статусы при этом продолжают обновляться.

Честный расход квоты в анонимном режиме: только зрители —
240 единиц/час при интервале 15 с; на 10-часовом эфире это 2 400 из
10 000 дневных единиц. Чат добавляет расход лишь в режиме официального
фолбэка.

### Настройки расширения и кастомный чат

Кнопка **⚙** в шапке док-панели открывает настройки расширения (применяются
сразу, сохраняются в `settings.json` вместе с настройками стрима):

- **Чтение чата YouTube** — `auto` / `innertube` / `official` (подсказка «?»
  описывает каждый режим). Смена режима во время эфира перезапускает
  ридер чата на лету.
- **Обновление зрителей** — интервалы в секундах отдельно для YouTube
  (5–120 с, каждый опрос — 1 единица квоты) и Twitch (бесплатно).
- **Токены** — кнопки «Проверить» (валидность без обновления) и «Обновить»
  (принудительный refresh) для Twitch и YouTube, с остатком времени
  жизни токена.
- **Формат сообщений чата** — строка с тегами:

  | Тег | Что выводит |
  |---|---|
  | `<time>` | время сообщения, ЧЧ:ММ |
  | `<time[%H:%M:%S]>` | время в своём формате (`%H %M %S %d %m %Y %y`) |
  | `<source>` | YT/TW — платформа (цвета как в чате) |
  | `<avatar>` | аватарка автора (YouTube — из API; иначе цветной круг с буквой ника, цвет детерминирован из ника) |
  | `<username>` | ник автора |
  | `<message>` | текст сообщения |

  Всё, что не тег, выводится как есть. Пример:
  `<time><avatar>[<username>] - <message>` →
  `02:05ⓐ[@develper] - привет`. Рядом — живое превью и подсказка «?» со
  всеми тегами. Формат действует и в чате панели, и в «чате для показа».
- **Чат для показа** — включите и скопируйте ссылку
  `http://127.0.0.1:<порт>/overlay` (кнопка ⧉), добавьте её как **Browser
  Source** на сцену OBS. Страница полностью прозрачна по альфе — видны
  только сообщения. Настройки: время жизни сообщения (5–600 с — чтобы
  чат не висел поверх стрима, если все замолчали) и максимум сообщений
  (1–50 — старые вытесняются новыми, память не растёт).

| `config.py` | константы, endpoints, пути папки данных |

## Устранение проблем

- **«obs-multi-rtmp не найден»** (кнопка запуска заблокирована) — установите
  obs-multi-rtmp 0.6+ и перезапустите OBS.
- **«Нельзя перезагружать цели во время стрима»** — остановите основной
  стрим OBS и повторите.
- **«Смена профиля при активной записи небезопасна»** — остановите запись:
  перезагрузка конфига obs-multi-rtmp идёт через смену профиля.
- **OBS лагает при двойном стриме** — выберите аппаратный кодер
  (NVENC/QSV/AMD) в настройках вывода OBS: кодеры обеих платформ
  берутся оттуда. Также помогают снижение битрейтов, разрешения
  вывода или FPS.
- **Цель YouTube не стартует / ошибка кодера** — откройте док
  obs-multi-rtmp и лог OBS: выбранный в OBS кодер недоступен для цели
  (например, проблема драйвера GPU).
- **Дорожка звука Twitch не применяется** — дорожки выбираются в док-панели
  для каждой платформы; для YouTube выбор работает всегда, а для Twitch
  (основной выход OBS) — только в Advanced-режиме вывода: Simple-режим
  OBS физически стримит один общий микс (дорожка 1). При конфликте в лог
  док-панели выводится предупреждение.
- **Док-панель не открывается** — проверьте `http://127.0.0.1:7664/debug`
  и порт в настройках скрипта (порт занят → смените и перезагрузите скрипт).
- **«YouTube чат: официальный API — квота тратится»** — анонимный канал
  недоступен (смена формата/блокировка IP): плагин сам вернётся на него при
  восстановлении; чат при этом работает. Если не нужен официальный фолбэк —
  поставьте `YOUTUBE_CHAT_SOURCE = "innertube"` в `config.py`.
- **Чат YouTube молчит в режиме `innertube`** — анонимный канал ломается
  редко (смена формата/блок IP); верните `"auto"` в настройках расширения
  (⚙), чтобы работал каскад с официальным фолбэком.
- **Оверлей пустой/чёрный фон** — включите «Чат для показа» в ⚙ и добавьте
  источник по ссылке `http://127.0.0.1:7664/overlay`. Проверить страницу
  можно и в обычном браузере: там фон будет белым — это нормально,
  прозрачность по альфе видна только внутри OBS (Browser Source).
