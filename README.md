# OBS Multi-Stream

Одновременный стрим на **Twitch** и **YouTube** из одного OBS — одной кнопкой,
с единой панелью управления: авторизация → настройка → эфир.

Никаких ручных трансляций в YouTube Studio, копирования ключей и дублирования
настроек: плагин сам создаёт трансляцию, применяет название/игру/теги/превью,
поднимает оба RTMP-потока и ведёт объединённый чат.

## Возможности

- **Единая док-панель** (Custom Browser Dock): пошаговый визард — авторизация,
  настройки, эфирный экран со статусами, зрителями и чатом обеих платформ.
- **Вход без бумажной волокиты**: Twitch — код активации в панели (ссылка
  открывается в системном браузере), YouTube — вход прямо в панели OBS с
  авто-возвратом (клиент OBS встроен, свой Google-клиент не нужен).
- **Настройки трансляции**: название, описание, теги-чипы (как в YouTube:
  запятая/Enter — тег становится блоком с ✕, пробелы → подчёркивания),
  игра/категория с живым поиском, превью-микрокарточка (клик = замена).
- **Пресеты** с автосохранением: изменения выбранного пресета пишутся в него
  автоматически; последний активный пресет открывается сам.
- **Битрейт и дорожка звука отдельно для каждой платформы** (Twitch | YouTube),
  с предупреждением при превышении лимита Twitch (6000 Kbps по официальным
  рекомендациям).
- **Восстановление после сбоя**: если OBS/ПК упали во время эфира, следующий
  запуск **продолжает ту же трансляцию YouTube** (та же ссылка, чат и зрители),
  а не создаёт новую.
- **Безопасное хранение**: токены — в одном зашифрованном файле
  (`secrets.dat`; Windows — DPAPI, другие ОС — потоковый шифр с отпечатком
  машины). Всё локально, телеметрии нет.

## Как это работает

Плагин — это Python-скрипт OBS + встроенный HTTP/WebSocket-сервер
(`127.0.0.1:7664` / `7665`), который отдаёт страницу док-панели и обменивается
с ней командами. Второй RTMP-вывод обеспечивает движок
[obs-multi-rtmp](https://github.com/sorayuki/obs-multi-rtmp): плагин записывает
в него обе цели (Twitch + YouTube со своими битрейтами и дорожками звука) и
стартует их синхронно с основным выходом OBS (основной выход при этом уходит
в локальный RTMP sink и отбрасывается).

```
OBS ──► obs-multi-rtmp ──┬──► Twitch (RTMP, свой кодер)
                         └──► YouTube (RTMP, свой кодер)
       Python-скрипт ──► YouTube Data API (broadcast/превью/категория)
                      ──► Twitch Helix (ключ, title/игра/теги)
       Док-панель (CEF) ⇄ HTTP+WS ⇄ скрипт
```

## Требования

- **OBS Studio 30.2+** (работает и на 32.x — управление профилями идёт через
  obs-frontend-api напрямую).
- **obs-multi-rtmp 0.6+** (sorayuki).
- **Python**, который использует OBS, + два пакета:

  ```
  pip install websockets websocket-client
  ```

  (`websockets` — док-панель, `websocket-client` — чат Twitch).
  obs-websocket Server не нужен.

## Установка

1. Установите **obs-multi-rtmp 0.6+**:
   https://github.com/sorayuki/obs-multi-rtmp — и перезапустите OBS
   (плагин должен появиться в меню Docks: «Multiple RTMP outputs»).
2. Папку `obs_multi_stream` добавьте в скрипты OBS:
   `Tools → Scripts → Script Files → +`.
3. Установите Python-пакеты (см. «Требования»).
4. Добавьте док-панель: `View → Docks → Custom Browser Docks`,
   URL: **`http://127.0.0.1:7664/`**

## Быстрый старт

### Шаг 1 — Авторизация

- **Twitch**: «Подключить Twitch» → в карточке появится код (клик —
  копирует; кнопка открывает `twitch.tv/activate` в системном браузере,
  код уже в ссылке) → подтвердить. Панель продолжится сама.
- **YouTube**: «Подключить YouTube» → **«Войти здесь — в панели OBS»**
  (панель уходит на страницу Google и возвращается автоматически) или
  «Во внешнем браузере» — системный браузер. Клиент OBS встроен в плагин,
  свой Google-клиент создавать не нужно (опция есть в «Расширенных»).

### Шаг 2 — Настройки

Все поля автосохраняются (~0.8 с после правки, индикатор «✓ сохранено»):

- **Название / Описание** — как обычно.
- **Игра** — начните вводить название: появятся подсказки (Twitch-игры +
  категории YouTube); Enter выбирает первую. После выбора — компактный чип
  с бейджем категории YouTube (клик по бейджу — уточнение, клик по чипу —
  редактирование).
- **Теги** — чипы как в YouTube Studio: запятая или Enter превращают текст
  в блок с ✕; пробелы внутри тега автоматически заменяются на `_`
  (транскоды/хэштеги не любят пробелы). Backspace на пустом поле удаляет
  последний тег.
- **Превью YouTube** — микрокарточка: клик по картинке заменяет файл,
  ✕ в углу убирает; поддерживается drag&drop (JPG/PNG до 2 МБ).
- **Битрейт и дорожка звука** — колонки Twitch | YouTube: степперы ±500
  и сегменты 1–6. Если битрейт Twitch выше 6000 Kbps — появится
  предупреждение (официальный рекомендуемый максимум; выше — возможны
  отключение транскодов и нестабильность).
- **Пресеты** — «＋» создаёт новый (поповер с именем); выбранный пресет
  обновляется автоматически при каждой правке настроек, отдельная кнопка
  перезаписи не нужна; ✎ — переименовать, ✕ — удалить. Последний выбранный
  пресет открывается сам при следующем запуске OBS.

Дорожка звука — какой «Трек 1–6» микшера OBS идёт в эфир платформы. По
умолчанию Трек 1 (на него звук источников OBS идёт изначально). Настраивать
стоит, только если вы развели звук по трекам: правый клик по источнику →
«Расширенные свойства звука» → галочки «Трек 1…6».

### Шаг 3 — Запуск

Кнопка **«▶ Запустить стрим (Twitch + YouTube)»**:

- Twitch: stream key через API, обновление названия/игры/тегов канала.
- YouTube: создание broadcast + переиспользуемый stream + привязка,
  категория, превью, автопереход в `live` (с ретраями).
- obs-multi-rtmp стартует оба потока своими кодерами; в панели — статусы,
  зрители и объединённый чат.

Остановка — «■ Остановить стрим»: трансляция YouTube завершается (`complete`),
профили OBS восстанавливаются из бэкапа. Если эфир был начат/остановлен
кнопкой OBS — плагин отслеживает это тоже.

### Если OBS или ПК упали во время эфира

Плагин сохраняет активную трансляцию YouTube в `live_session.json`. После
перезапуска OBS панель предупредит: «найдена незавершённая трансляция» — и
следующий запуск **продолжит её**: та же ссылка, тот же чат и счётчик
зрителей, без новой записи на канале. Twitch в восстановлении не нуждается —
название/игра просто применяются заново. Явная остановка («■») завершает
сессию; следующее нажатие «▶» создаёт новую трансляцию.

## Где хранятся данные

Всё — в одной папке (одна папка = полное удаление плагина):

| Путь | Что лежит |
|---|---|
| `<obs-config>/plugin_config/multistream/secrets.dat` | токены/клиенты (зашифровано) |
| `…/multistream/settings.json` | настройки стрима + последний пресет |
| `…/multistream/presets.json` | пресеты |
| `…/multistream/previews/` | файлы превью |
| `…/multistream/live_session.json` | активная трансляция (для восстановления) |
| `…/multistream/backup/` | бэкапы профилей на время эфира |
| `…/multistream/multistream.log` | лог плагина |

`<obs-config>`: Windows — `%APPDATA%\obs-studio`, macOS —
`~/Library/Application Support/obs-studio`, Linux — `~/.config/obs-studio`.
Диагностика сервера панели: `http://127.0.0.1:7664/debug`

Токены не покидают машину: шифрование секретов — DPAPI (Windows) или
потоковый шифр с отпечатком машины (другие ОС), запись атомарная.

## Структура проекта

| Файл | Назначение |
|---|---|
| `obs_multi_stream.py` | главный модуль: визард, запуск/остановка стрима, восстановление |
| `omr_bridge.py` | движок: цели obs-multi-rtmp, sync-start, профиль-свитч, RTMP sink, бэкапы |
| `obs_bridge.py` | мост к OBS: извлечение YouTube-клиента из бинарника, чтение basic.ini |
| `oauth_flow.py` | OAuth Twitch (DCF, refresh через прокси OBS) и YouTube (loopback/PKCE) |
| `twitch_api.py` / `youtube_api.py` | обёртки Helix / YouTube Data API v3 |
| `dock_server.py` + `dock.html/css/js` | док-панель (HTTP 7664 + WS 7665) |
| `twitch_chat.py` / `youtube_chat.py` / `viewer_counter.py` | чаты и зрители |
| `secret_store.py` | хранение секретов (secrets.dat) |
| `config.py` | константы, endpoints, пути папки данных |

## Устранение проблем

- **«obs-multi-rtmp не найден»** (кнопка запуска заблокирована) — установите
  obs-multi-rtmp 0.6+ и перезапустите OBS.
- **«Нельзя перезагружать цели во время стрима»** — остановите основной
  стрим OBS и повторите.
- **«Смена профиля при активной записи небезопасна»** — остановите запись:
  перезагрузка конфига obs-multi-rtmp идёт через смену профиля.
- **OBS лагает при двойном стриме** — снизьте битрейты, разрешение холста
  или FPS; можно сменить preset кодера в доке obs-multi-rtmp
  (Правка цели → Video).
- **Основной выход не подключается к локальному RTMP sink** — проверьте,
  что антивирус/файрвол не блокирует localhost; детали — в логе OBS.
- **Док-панель не открывается** — проверьте `http://127.0.0.1:7664/debug`
  и порт в настройках скрипта (порт занят → смените и перезагрузите скрипт).
